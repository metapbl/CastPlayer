## 1. 목적
- 해결할 문제: Windows PC에 있는 로컬 동영상 파일을 Chromecast with Google TV(4세대)로 보내는 가벼운 GUI 프로그램. PC에서는 동영상을 재생하지 않고 제어 화면만 띄운다 [X] C §1
- 사용자 (누가, 몇 명, 어떤 기기): 본인(개발·주 사용자, Windows 11 PC → Chromecast with Google TV) [X] C §3 + GitHub에서 받아 쓰는 일반 사용자 [U] (D039). Windows 11 공식 지원, Windows 10은 미시험 표기. 화면 한국어, README 한국어+영어 [U] (D040)
- 성공 기준 (관찰 가능한 장면 하나): GUI로 영화 한 편을 처음부터 끝까지 본다. 중간에 연결이 끊겨도(랜선 수십 초 분리 포함) 손대지 않고 이어지고, 잦던 버퍼링(옛 기록: 약 2시간에 약 20회)이 해결됐음을 확인한다. 끊김 기준: 재생 중·일시정지 중 각 1회 랜선 30초 분리 후 꽂으면 60초 안에 조작 없이 같은 위치(±10초)·같은 상태로 이어짐. 버퍼링 기준: 영화 한 편(약 2시간)에 2회 이하, 로그의 재생 상태 전환 PLAYING→BUFFERING 횟수로 판정(조작 뒤 10초 안은 제외) [U] (D036, D050, D051)
- 기한과 수명 (언제까지, 다 쓰면 폐기/유지): 기한 없음, 계속 쓰며 유지 [U] (D038)

## 3. 기능
### F1 기기 검색·연결
- 정상 흐름: 시작 시 mDNS 검색 → 저장 UUID가 보이면 자동 연결. 8초 뒤에도 연결 전이면 저장 IP를 known host로 추가 → 8초 뒤에도 없으면 포기 안내. 메뉴에서 IP로 기기 추가 [X] C §8 main_window
- 예외: TV가 꺼져 있으면 자동 연결 실패가 정상 동작 [X] P 4단계 1차. IP로 기기 추가에 IPv4가 아닌 값을 넣으면 "올바른 IP 주소가 아닙니다: …" 경고 뒤 입력한 글자를 둔 채 입력창이 다시 뜸 [X] `ui/dialogs.ask_ip` (D069)
- 다른 기기 연결: 재생 중 다른 기기의 [연결]을 누르면 지금 기기의 재생을 정지(수신 앱 종료)하고 연결을 끊은 뒤 새 기기에 연결, 끊김 기억은 지움. 끊긴 같은 기기에 다시 연결할 때만 이어 감 [X] `ui/main_window._connect`, `cast_manager._do_connect` (D069)
- 기기 찾기 현황 (상태줄): 시작할 때·F5·IP로 기기 추가 때 왼쪽에 "기기 찾는 중…", 새 기기가 나타날 때마다 "기기를 찾았습니다: {이름}", 8초 뒤 "기기 찾기 완료: {n}대". 하나도 없으면 경고색 "기기를 찾지 못했습니다. 같은 네트워크인지 확인하거나 메뉴 → IP로 기기 추가를 쓰세요." 찾는 동안 파일이 없으면 오른쪽에 "기기 찾는 중 · {n}대". mDNS에는 끝 신호가 없어 8초로 끊음. 연결된 동안의 F5는 목록만 다시 알리므로 바로 완료. 자동 연결이 저장된 IP로 확인하는 중이면 실패 알림은 그쪽("…을(를) 찾지 못했습니다.")에 맡김 [U] (D120) · 8초·문구 [AI]
- 상태별 동작: 연결 전에는 파일 열기·끌어다 놓기 잠김. 연결 표시 회색 미연결 / 노랑 연결 중 / 초록 연결됨 / 빨강 다시 연결 중. 포기 안내 뒤에는 기기 목록에서 [연결]을 직접 누름 [X] C §8 main_window
- 인터페이스: `CastManager.start_discovery/add_known_host/rescan/connect/disconnect`, `CastCallbacks`, `config.json`(`last_device_uuid`, `last_device_host`, `known_hosts`, `auto_connect`) [X] C §8
- 인수 기준 (D061, 확인: [자동] = `--selftest`, TV 없이 가짜 cast·기기 목록·로그 수집으로 모의 / [실기기] = 사용자 확인):
  - F1-1 [자동]+[실기기] Given 저장된 기기가 켜져 있고 같은 네트워크에 있음 / When 프로그램을 시작 / Then 조작 없이 연결되고 연결 표시가 ● 초록 [X] (자동: 가짜 기기 목록에서 자동 연결·● 초록, D071)
  - F1-2 [자동] Given 기기에 연결되지 않음 / When 파일을 끌어다 놓음 / Then 열리지 않고 "먼저 기기를 연결하세요." 안내 [X] (D071)
  - F1-3 [자동]+[실기기] Given 저장된 기기의 TV가 꺼져 있음 / When 프로그램을 시작 / Then 20초 안에 "…을(를) 찾지 못했습니다." 안내, ● 회색 [X] (8초 + 8초, 20초는 [AI] 여유) (자동: 못 찾으면 안내·● 회색. 실제 20초 안은 실기기, D071)
  - F1-4 [자동] Given 목록에 기기가 아직 없음 / When [연결]을 누름 / Then 10초 안에 나타나면 연결, 아니면 "기기 정보를 찾을 수 없습니다." [X] (D033)
  - F1-5 [자동]+[실기기] Given 검색(mDNS)에 보이지 않는 기기 / When 메뉴 → IP로 기기 추가에 IP를 넣음 / Then 목록에 나타나 연결할 수 있음 [X] (자동: IP 추가 뒤 목록에 나타나 연결, D071)
  - F1-6 [자동] Given 가짜 기기 목록 / When 찾기 시작 → 기기 1대가 나타남 → 찾기 시간이 끝남 / Then "기기 찾는 중…" → "기기를 찾았습니다: …"(오른쪽 "기기 찾는 중 · 1대") → "기기 찾기 완료: 1대". 기기가 없으면 경고색 "기기를 찾지 못했습니다…" [U] (D120)
- 확인 방법: 인수 기준의 표시대로. 자동은 `--selftest`, 실기기는 §6의 확인 결과 형식 (D062)
- 근거: D026, D120
### F2 불러오기·송출 방식 결정
- 송출 방식 규칙: 영상이 수신기 미지원(H.264 High 5.1 초과·10bit, HEVC Main/Main10 5.1 초과, 그 밖 코덱, 표시 시각 결함)이면 TRANSCODE. 아니면 mp4가 아님·HEVC 태그가 hvc1 아님·음성 변환 필요·첫 번째가 아닌 음성 트랙 중 하나라도 있으면 REMUX, 없으면 DIRECT [X] 코드 `planner.make_plan` (D010, D015, D024, D046)
- 정상 흐름: probe → 계획(DIRECT / REMUX / TRANSCODE) → 키프레임 분석(REMUX) → 자막 준비 → 송출. DIRECT는 mp4 파일 그대로, 나머지는 HLS VOD(fMP4) [X] C §8 player·planner·hls
- 키프레임 분석: MKV는 Cues, MP4는 stss 목차만 읽는다. 목차가 없거나 깨졌거나 MKV 목차의 키프레임 평균 간격이 10초를 넘거나 TS·AVI 등이면 파일 전체를 읽는다 [U] (D098) · 10초 [AI] (D101). 분석 결과는 캐시에 남기지 않는다(1GB TS·AVI 전체 읽기 실측 1초 안팎, 디스크 속도가 정함) [U] (D103)
- 내장 자막 뒤에서 추출: 자막 캐시가 없으면 추출을 3초만 기다리고, 넘으면 내장 자막 없이 재생부터 시작해 추출은 뒤에서 계속한다. 추출 중 자막 목록의 내장 자막은 회색 "추출 중 n%". 끝나면 상태줄 "내장 자막을 준비했습니다.", 자동 선택이 내장 자막을 고를 때만 그 자리에서 한 번 다시 불러옴(일시정지 유지, 끊긴 동안이면 복구 뒤). 사용자가 나중에 내장 자막을 고르면 그때 한 번 다시 불러옴. 정지·새 파일·사용자 연결 해제·종료·재연결 포기 때 추출을 끝내고 캐시를 남기지 않음, 끊긴 동안·음성 변경은 계속 [U] (D107~D110, D112) · 문구·세부 [AI]
- 자막 추출 진행률은 ffmpeg가 파일을 읽은 양(바이트)으로 계산한다. 자막 시각 기준은 듬성한 트랙 때문에 멈춘 듯 보임(실측 8→22→73→98%) [AI] (D115). 추출 중 정지했다가 다시 재생하면 재생을 먼저 시작하고 추출을 처음부터 다시 [U] (D116)
