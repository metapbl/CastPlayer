# GUI 자동 시험과 인수 기준 재분류 반영 (D071)
상태: active | 시작: 2026-10-29 | 근거: PRD §6, F1·F2·F3·F4·F5·F6·F7 (D071)

목표: PRD에서 [자동]·[자동]+[실기기]로 다시 표시한 인수 기준 18개의 자동 부분과 PROGRESS "확인 대기"의 자동 가능한 항목이 `--selftest`로 확인된다. 실기기 시험에는 TV 실제 동작만 남는다.
구조:
- `tools/cast_test.py` — 화면 없는 Qt(`QT_QPA_PLATFORM=offscreen`)로 실제 `MainWindow`를 띄우는 시험 틀(`_GuiCM`: `_FakeCM`에 GUI가 부르는 명령 기록 추가, 진짜 `CastBridge`·`PlaybackController`)과 자가검사 묶음 `_gui_cases`(새). 코어 쪽 기준은 기존 `_fresh()` 대역 사용
- `main.py` — 종료 정리 세 줄(`cm.shutdown` → `ctrl.shutdown` → `server.stop`)을 함수 하나로 뺌. F3-6 자동 부분을 시험하려고 (동작 변경 없음)
- `docs/PROGRESS.md` — "확인 대기" 중 자동으로 옮긴 항목 정리
전역 제약:
- 작업마다 `--selftest` 전부 통과, 전체 15초 이내 (D064, D071). 편집 때 ruff·pyright 통과 (D063, D068)
- 테스트 코드는 `tools/cast_test.py`에만 (D031). core에서 Qt import 금지 (D003)
- 지금 동작을 고정하는 시험(특성 시험)이라 처음부터 통과해야 함. 실패하면 그 자리에서 멈추고 원인(시험 틀 문제 / 코드 버그)을 보고한 뒤 진행 방식을 묻는다
- 기다리는 시간 상수(`AUTO_HOST_FALLBACK_MS`, `RECONNECT_WINDOW`, `SLOW_SEND`)는 시험 안에서만 줄이고 끝나면 되돌린다. 전역 대역(`local_ip_for`·`make_plan`)도 같다
- 시험 이름에 기준 번호를 붙인다 (예: `F3-2 → 연타 → 탐색 1번`)
- 시제품(2026-10-29, 저장소 밖)으로 확인한 것: 창이 0.1초 만에 뜸, 연결 신호 뒤 ● 초록, Space → pause, → 3번 → 탐색 1번(+15초), ↑ → 볼륨 0.55, M → 음소거, S → 정지
